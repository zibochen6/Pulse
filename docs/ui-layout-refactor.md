# Popover layout and interaction

Pulse's 360×510 menu bar popover now has a Home page and a Settings page. Home presents the Pulse header, a compact Codex Usage summary, and a Tasks disconnected state. It shows every Codex quota window returned by the existing usage controller, including each window's remaining percentage and reset time, plus the latest update time. The Refresh button still asks that controller to fetch again. A failure or unavailable result remains an explicit message rather than a made-up percentage.

The gear button opens Settings inside the same popover. Add Provider and Connect Obsidian open the Providers and Tasks explanation sections there; neither starts an integration. General holds the two existing UserDefaults preferences and reports the actual macOS Login Items status. About reads the bundle version when available, otherwise says “Development build”, credits the menu icon, and opens the bundled THIRD_PARTY_NOTICES.md. The back button returns to Home. This leaves space for future provider rows and real task rows without presenting placeholders as user data.

AppKit still owns one NSStatusItem and one transient NSPopover. A second status-item click toggles the popover, and an outside click dismisses it immediately. Tracking areas on the status button and popover content report pointer entry and exit. When the pointer is outside both, a cancellable 400 ms task schedules closure; re-entry cancels it. On opening, the current pointer position initializes the state. Before delayed closure, the controller checks the actual pointer against the status button and entire popover window, including its arrow. If the window contains the pointer but no entry event arrived, it checks again after 400 ms so a later departure can still close the panel. Any popover close clears the pending task. Internal scrolling, buttons, and page changes do not request closure.

## Verification

Run xcodegen generate after adding source files, then use the build and test commands in the README. Unit tests use a simulated login item service and usage provider, exercise the pointer delay/cancellation/reset decisions, and render Home and Settings in light and dark appearances. The renderer checks that the full surface stays opaque.

On 2026-09-28, the Debug build and 29 tests passed; strict swift-format lint and git diff whitespace checks also passed. The built app launched and remained running during a short process smoke check, its bundle reported LSUIElement=true, and third-party notices were present in the bundle. This environment did not provide a reliable live view of the menu bar popover, so click-to-toggle, outside click, pointer tracking geometry, navigation/back, refresh, Quit, and dark mode still need interactive desktop inspection. Automated rendering and pointer state tests do not prove those mouse-event paths.
