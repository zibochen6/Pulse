# Apex Dashboard 首次连接流程

## 五分钟内完成的流程

从 Home 的“连接 Obsidian”进入 Settings → Tasks。用户先通过 Finder 选择 Vault 文件夹，再选择该 Vault 内的 Dashboard Markdown 文件。选择顺序让用户明确 Pulse 可以读取的范围；Pulse 不写死开发者的 Vault 路径，也不默默扫描整个主目录。Dashboard 可以位于 Vault 任意位置，不能仅凭文件名推断。

选定文件后，验证它是 Vault 内可读的 `.md` 文件，且有 Apex Dashboard 所需的文件头与列／卡片结构。成功时展示“已连接”、文件名和一次读取结果；用户可重新选择 Vault 或文件。初次连接可以跳过，Codex 状态仍可使用。

## `DashboardConnectionState`

| 状态 | 进入条件 | 界面反馈与下一步 |
| --- | --- | --- |
| `unconfigured`（未配置） | 尚未选定 Vault 和 Dashboard | 显示选择入口，不显示虚构任务。 |
| `fileMissing`（文件不存在） | 之前选择的文件已删除或移动 | 说明原选择失效，提供“重新选择文件”；不自动切换到同名文件。 |
| `parseFailed(reason)`（解析失败） | 文件存在，但未能得到可用快照 | `reason` 区分无权限、无法读取、编码错误、非 Dashboard 文件和结构不匹配。权限错误显示“无法读取文件”，不能显示成“文件不存在”或声称 Markdown 格式有错；提供重试与重新选择。 |
| `connected(snapshot)`（已连接） | 文件成功读取、校验、解析 | 展示真实列／卡片／任务和最近读取时间。 |

四种状态是界面连接状态；`reason` 保存可操作的失败原因。`parseFailed` 这个名称不应迫使所有失败都显示“解析失败”：读取权限失败须使用准确文案。读取失败时不把旧快照当作最新任务。

## 本地配置与路径安全

当前 GitHub 下载版未启用 App Sandbox。设计上仅在本机偏好中保存用户选择的 Vault 位置和相对 Dashboard 路径，不保存任务文本；运行时组合成 `fileURL` 并重新校验。未来若发行沙盒版，需要安全范围书签和权限恢复流程，不能假设普通路径字符串足够。

文件选择与读取应解析符号链接并确认目标仍在所选 Vault 内。Vault 移动、文件重命名、权限撤销及无法解码时，保持清晰状态并让用户重新选择或重试；不得静默读取别的文件。错误日志只记录错误类别，不输出绝对路径、任务内容或插件配置。用户关闭并重新打开弹窗会重新读取文件，Tasks 顶部也有手动刷新；首版不安装文件监听器。
