# Pulse 0.1.3 (build 7)

## Changes

- Add a self-built in-app updater. Pulse checks the public GitHub latest-release
  feed about ten seconds after launch and every six hours while running, and
  Settings → Updates offers **Check Now**; automatic checks can be turned off.
  A newer release is downloaded as `Pulse-<version>.zip` in the background and
  accepted only after HTTPS and redirect-host checks, SHA-256 verification
  against the release `.sha256` asset and the GitHub asset digest, archive
  layout, bundle identifier, embedded version, code signature and signing
  team/authority checks pass. A failed check discards the download and leaves
  the installed app untouched.
- Install a verified update in the background, but restart Pulse to apply it
  only when the popover is closed and no task draft is open. Otherwise a
  "Pulse 0.1.x is ready" banner with **Restart** and **Later** appears above
  the task list, and the update is applied on quit. An update never touches
  `tasks.json`, UserDefaults or Keychain items.
- Redesign the native to-do surface: tag-only tabs with a filled capsule
  selection and no square focus ring, a centered `+` under the list for quick
  add, a `+` menu at the end of the tag row to add a task in another or a new
  tag, completed tasks kept visible under a "Completed" heading (dimmed and
  struck through) with hover-to-delete plus confirmation, and an optional
  per-task "Repeat daily" that re-arms the next day.
- Remove the Obsidian / Apex Dashboard integration entirely: Markdown parsing,
  the file picker, checkbox write-back and the task-source switch. Pulse now
  has exactly one task system. Existing user Markdown files and bookmarks are
  untouched; Pulse simply stops reading them.

## Installation

Download `Pulse-0.1.3.dmg` and its `.sha256` file from the
[GitHub release](https://github.com/zibochen6/Pulse/releases/tag/v0.1.3).
The app supports macOS 13+, Apple Silicon (`arm64`) and Intel (`x86_64`).

Quit the previous Pulse instance, open the DMG, drag Pulse into Applications
and launch the installed app. Replacing the bundle preserves existing task
storage, settings and Keychain items. Do not run an old development build
simultaneously.

The release publishes four assets: `Pulse-0.1.3.dmg` and
`Pulse-0.1.3.dmg.sha256` for manual installation, plus `Pulse-0.1.3.zip` and
`Pulse-0.1.3.zip.sha256`, which the in-app updater consumes for later
releases. The DMG and ZIP contain the same signed app.

In the download folder, verify a checksum with:

```sh
shasum -a 256 -c Pulse-0.1.3.dmg.sha256
shasum -a 256 -c Pulse-0.1.3.zip.sha256
```

Pulse 0.1.3 is the first release with the updater, so moving from 0.1.2 to
0.1.3 is a manual DMG install. From 0.1.3 on, Pulse downloads and verifies a
newer release in the background and stages it for installation. The staged
update restarts the app only when the popover is closed and no task draft is
open; otherwise a "Pulse 0.1.x is ready" banner with **Restart** and **Later**
appears above the task list, and quitting applies it. The previous app is
backed up to
`~/Library/Application Support/Pulse/Backups/` before replacement and restored
if installation fails; progress is logged to
`~/Library/Logs/Pulse/update.log`. Updates are enabled only when Pulse runs
from a user-writable `/Applications/Pulse.app`; development builds report that
updates are disabled.

This preview uses Apple Development signing, **not Developer ID signing or
notarization**. macOS may block first launch. If you trust the build, follow
[Apple's app-opening guidance](https://support.apple.com/102445) using the
available Open Anyway option; do not disable Gatekeeper. This release is not
a claim of fresh-machine or notarized-distribution acceptance.

## Validation

0.1.3 is accepted on the following evidence. The release run records the final
test totals, so this note states the gate rather than guessing counts.

- Unit and render suite: the full suite is expected to pass with no failures.
  Automated tests use synthetic provider responses, isolated credential stores
  and temporary task files rather than real accounts.
- Updater unit tests cover version comparison, latest-release and asset
  parsing, checksum verification, the verification chain's rejection cases and
  install-script generation.
- End-to-end update rehearsal: a local feed supplied through
  `PULSE_UPDATE_FEED_URL` presents a higher version, and the full verification
  chain still runs. The staged app replaces the installation, and a deliberate
  failure restores the backup. The rehearsal leaves task data, preferences and
  Keychain items unchanged.
- Signed universal Release build for `arm64` and `x86_64`, macOS 13 minimum,
  built through `./scripts/release.sh 0.1.3`. The read-only mounted DMG and the
  updater ZIP pass signature, 0.1.3/build 7 metadata, architecture,
  executable-hash equality and SHA-256 checks. Published `.sha256` assets and
  GitHub asset digests match the local files.
- `release.sh` installs the verified build locally before pushing and tagging.
  The installed app, the DMG and the ZIP are the same signed build, and one
  instance runs from `/Applications/Pulse.app`.
- Native menu clicks, scrolling, inline editing and hover animation are not
  certified by unit/render checks; a direct desktop pass is reported
  separately from the automated checks.

## Current limits

Auto-updates start with 0.1.3: earlier releases have no updater and cannot
update themselves, so this version must be installed from the DMG once.
Updates require reachability to GitHub and a user-writable
`/Applications/Pulse.app`; development builds and other locations report that
updates are disabled. There is no delta update, no appcast and no separate
signing key.

The updater is self-built rather than Sparkle. It trusts transport HTTPS, the
published release digest and the Apple code signature bound to the developer
certificate. If Pulse moves to Developer ID signing, notarization or CI
signing, migrating to Sparkle becomes worthwhile.

An update is applied on restart (or on quit when the banner is visible); it
does not modify the installed app while a draft or the popover is in use. The
release remains an Apple Development-signed preview and does not certify
notarized or fresh-machine distribution.

Markdown files, bookmarks and previous integrations are not read, imported or
deleted. The native to-do list is the only task system, and existing
`tasks.json` data, preferences and credentials remain compatible.
