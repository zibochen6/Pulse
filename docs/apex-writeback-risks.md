# Apex Dashboard 未来写回风险

## 当前决策

首版 Pulse 只读，不勾选、新增、编辑、移动或删除任务。用户在 Pulse 点击任务只会在 Obsidian 打开源 Markdown 文件。以下内容用于约束未来单独立项的写回工作，不是当前实现承诺。

## 为什么不能直接替换文本

已安装的 Apex Dashboard 1.4.4 在任务变化后会把内存中的 Dashboard 重新序列化并重写整个 Markdown 文件，并尝试生成旧内容备份。已完成的顶层任务还可能被重排。Pulse 若依据曾经读到的行号执行 `replace`，很可能改到另一条任务；同一段文字可以出现多次，单靠任务文本也无法唯一定位。

| 风险 | 未来写入前必须验证的行为 |
| --- | --- |
| Markdown 与 Apex 结构 | 保留 YAML、列／卡片顺序、卡片 ID、缩进、换行、BOM、提醒与插件注释；不能通过重建文档丢失未理解的字段。 |
| 外部修改 | Obsidian、Apex 插件或同步工具可能在 Pulse 读取后修改或替换文件；写入前必须重新读取并比对文件身份、内容摘要及目标任务上下文。 |
| 重复任务与行号漂移 | 相同文本、任务重排或卡片移动会使旧行号失效；无法唯一匹配时停止，提示刷新，不猜测目标。 |
| 并发写入 | “比对后写入”与另一个编辑器写入之间仍可能竞争；需要文件协调与真实并发测试，不能宣称哈希比对完全消除竞态。 |
| 原子性与备份 | 将变更写入同目录临时文件并原子替换时，还要保留权限等文件属性，确认 Obsidian 能感知更新；独立备份和恢复流程要与插件自有备份共存。 |
| 插件版本 | 插件的序列化和任务语义可能变化；必须按受支持版本建立脱敏兼容样本，不把当前源码当成永久协议。 |

未来可以评估插件内协作接口或受约束的原文字节级修改，但无论选择哪条路径，都要先用**临时 Vault 副本**验证勾选、新增、冲突、格式保持、插件再次保存和恢复。个人 Vault 始终只读用于研究。首版仅提供打开原文件，让 Obsidian 继续负责实际编辑。
